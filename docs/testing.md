# 검증과 배포

## 개발 중

의존성은 최초 또는 lockfile 변경 시 설치합니다. 관련 단위·UI 검사부터 실행하고 동일 코드의 통과 결과를 재사용합니다. 문서만 변경했다면 포맷·diff·링크 검사로 충분합니다. 테스트를 삭제/약화해서 통과시키지 않습니다.

```sh
npm run format
npm run lint
npm run typecheck
npm test
npm run build
npm run test:e2e
```

Vitest와 Playwright는 작업자1개, 합성 데이터만 사용합니다. Playwright가 전용4180 서버를 소유하며 사용자 프로필은 사용하지 않습니다. Windows에서는 기존 테스트용 브라우저 경로를 해당 명령의 PLAYWRIGHT_BROWSERS_PATH로 지정합니다. 실행이 중단되거나 종료되지 않으면 통과로 계산하지 않습니다.

## 회귀 범위

- 계좌: 생성/수정/휴지/재개,100개 경계, 손상·읽기/쓰기 실패, 탭 간 충돌과 입력 보존.
- 월별: 실제 마이그레이션/롤백, 날짜·참조·중복·상한, commit 이후 반영, 누락/0/안전 정수 경계.
- 백업: 버전·정규화·왕복 복원, 미리보기/취소/추가/충돌/원자적 실패,32 MiB 한도.
- FIRE: 연율·정수 엔·반올림·첫 도달·미도달·100년·overflow와 임시 입력/비교 수명.
- 레이아웃:100자 이름, 최대 금액, 긴 오류,320~1440px, 카드/버튼/입력 경계와 표/금액 clipping.
- 차트: 실선 구간 분리와 관측점 보존에 더해 누락/계좌 구성 변경의 명시적 점선 연결,0/최대값 좌표, 포인터 툴팁·터치·슬라이더·키보드, 계좌/기간 필터와 확대/복원, 상세 이동, 확인 후 예측 입력, 범례·연도·비교 결과. 불연속4개 관측의 상승/하락 경로와 중간 미기록 상태를 검증합니다. 자산/투자/수입/지출 막대에도 실제 추세선이 있는지 확인합니다.
- 통일된 UI: theme.css 공통 토큰 사용, 자산/월별/계좌/FIRE/백업의 어두운 표면, 입력/상태/표/내비게이션 색상과 포커스를 확인합니다.320px의300px 이상 그래프 높이와1440px 각 섹션 실화면을 확인합니다.
- 브랜드 앱 셸: 문서 제목·설명·테마 색, SVG 파비콘·Apple touch icon·manifest 응답과 아이콘 크기를 확인합니다.390px에서5개 하단 탭의 고정 위치·아이콘·11px 이상 레이블·가로 넘침을 검사하고 reduced-motion의 전환 억제를 확인합니다.
- 문서: 현재 안내와 역사 분리, 상대 링크 존재, 기존 이력 보존.

스크린샷은 test-results에만 두고 커밋하지 않습니다. Chromium 검증은 모든 브라우저/접근성 인증을 뜻하지 않습니다.

## 출시 게이트

1. 로컬 검증과 민감정보/게시 파일 검토.
2. 최종 PR head의 CI 성공 확인 후 해당 SHA로 병합.
3. 병합 후 main CI와 GitHub Pages 워크플로 둘 다 성공 확인.
4. 공개 HTML HTTP200과 참조 JS/CSS를 검증 빌드의 SHA256과 비교.
5. PR에 검증된 head/merge SHA, Actions 링크, 실제 배포 결과 기록.

CI와 Pages는 현재 독립 워크플로입니다. Pages 성공만으로 main CI가 성공했다고 간주하지 않습니다. [작업 기록](work-log.md)에 실행 결과를, [출시 이력](release-history.md)에 링크를 남깁니다.
