# 검증과 배포

## 개발 중

의존성은 최초 또는 lockfile 변경 시 설치합니다. 관련 단위·UI 검사부터 실행하고 동일 코드의 통과 결과를 재사용합니다. 문서만 변경했다면 포맷·diff·링크 검사로 충분합니다. 테스트를 삭제/약화해서 통과시키지 않습니다.

```sh
npm run format
npm run lint
npm run typecheck
npm test
npm run build
npm run test:e2e
```

Vitest와 Playwright는 작업자1개, 합성 데이터만 사용합니다. Playwright가 전용4180 서버를 소유하며 사용자 프로필은 사용하지 않습니다. Windows에서는 기존 테스트용 브라우저 경로를 해당 명령의 PLAYWRIGHT_BROWSERS_PATH로 지정합니다. 실행이 중단되거나 종료되지 않으면 통과로 계산하지 않습니다.

## 회귀 범위

- 계좌: 생성/수정/휴지/재개,100개 경계, 손상·읽기/쓰기 실패, 탭 간 충돌과 입력 보존.
- 월별: 실제 마이그레이션/롤백, 날짜·참조·중복·상한, commit 이후 반영, 누락/0/안전 정수 경계.
- 백업: v1/v2/v3 정규화·왕복 복원, FIRE 계획 미리보기/추가/충돌, 취소와 원자적 실패,32 MiB 한도.
- FIRE: 연율·정수 엔·반올림·첫 도달·미도달·100년·overflow, 입력/비교 자동 저장·새로고침·다른 브라우저 복원, 탭 간 충돌과 손상 보존.
- 마이그레이션: DB v3→v4가 기존 기록을 다시 쓰지 않고 빈 firePlans(id)를 추가하며 실패 시 전체 롤백하는지 확인합니다.
- 레이아웃:100자 이름, 최대 금액, 긴 오류,320~1440px, 카드/버튼/입력 경계와 표/금액 clipping.
- 차트: 실선 구간 분리와 관측점 보존에 더해 누락/계좌 구성 변경의 명시적 점선 연결,0/최대값 좌표, 포인터 툴팁·터치·슬라이더·키보드, 계좌/기간 필터와 확대/복원, 상세 이동, 확인 후 예측 입력, 범례·연도·비교 결과. 불연속4개 관측의 상승/하락 경로와 중간 미기록 상태를 검증합니다. 자산/투자/수입/지출 막대에도 실제 추세선이 있는지 확인합니다.
- 통일된 UI: theme.css 공통 토큰 사용, 자산/월별/계좌/FIRE/백업의 어두운 표면, 입력/상태/표/내비게이션 색상과 포커스를 확인합니다.320px의300px 이상 그래프 높이와1440px 각 섹션 실화면을 확인합니다.
- 브랜드 앱 셸: 문서 제목·설명·테마 색, SVG 파비콘·Apple touch icon·manifest 응답과 아이콘 크기를 확인합니다.390px에서5개 하단 탭의 고정 위치·아이콘·12px 이상 레이블, 모든 표시 일본어의12px 이상 계산 크기와 가로 넘침을 검사하고 reduced-motion의 전환 억제를 확인합니다.
- 문서: 현재 안내와 역사 분리, 상대 링크 존재, 기존 이력 보존.

스크린샷은 test-results에만 두고 커밋하지 않습니다. Chromium 검증은 모든 브라우저/접근성 인증을 뜻하지 않습니다.

## 출시 게이트

1. 로컬 검증과 민감정보/게시 파일 검토.
2. 최종 PR head의 CI 성공 확인 후 해당 SHA로 병합.
3. 병합 후 main CI와 GitHub Pages 워크플로 둘 다 성공 확인.
4. 공개 HTML HTTP200과 참조 JS/CSS를 검증 빌드의 SHA256과 비교.
5. PR에 검증된 head/merge SHA, Actions 링크, 실제 배포 결과 기록.

CI와 Pages는 현재 독립 워크플로입니다. Pages 성공만으로 main CI가 성공했다고 간주하지 않습니다. [작업 기록](work-log.md)에 실행 결과를, [출시 이력](release-history.md)에 링크를 남깁니다.

## 목표 도달형 검증

`tests/unit/domain/goal-fire.test.ts`는 정확한 도달월, 현금 제외 인출, NISA 각 한도/연도 전환/취득액, 월별 반올림, 미도달/현금 부족/overflow를 검증합니다. `tests/e2e/goal-fire.spec.ts`는 합성 기록의 완료월 평균, 구성 금액/비율, 차트와 키보드, 입력 수정,320/390/1440px 넘침과 오류 상태를 확인합니다. 기존 FIRE 자동 저장 테스트도 함께 유지합니다.

## Milestone16 검증

목표 계획 단위 검증과 JSON v1~v4 보존/충돌 검증, goal-plan-storage의 실제 DB v4→v5 보존/롤백/탭 충돌/손상/초과, goal-plan-ui의 새로고침/빈 브라우저 복원/연도 경계를 추가합니다. 기존 검사의 현재 DB/JSON 기대 버전만5/4로 갱신하고 과거 버전 fixture는 유지합니다.

responsive-window.spec.ts는 같은 페이지를 새로고침 없이320~2560px로 반복 변경합니다. 본문 오른쪽 경계,1600px 경계에서 축소 없음, 데스크톱 확장과 차트 재측정,860px 한 열 전환, 가로 넘침과 pageerror를 검증합니다.

각 창 크기에서 SVG와 financial-plot 컨테이너 폭이 1px 이내로 일치할 때까지 확인한 뒤 측정합니다. 양수/화면 경계만으로는 ResizeObserver 반영 전의 이전 폭도 통과하므로 재측정 완료 조건을 함께 검사합니다. 기존 차트 확장 및 넘침 검증은 유지합니다.

## Milestone17 검증

withdrawal 단위 검사는 비례 매도, 원가/신규매수, 이익/손실/미상,0/100%세율, 소수3자리/정수 엔 반올림, 안전정수와 미도달을 확인합니다. goal-plan은 구13필드 이행과 v4/v5 형태 오류·원본/충돌 보존을 확인합니다. 실제 IndexedDB의 읽기/내보내기 원본 불변과 편집/탭/복원 충돌, 새 필드의 새로고침·빈 브라우저 JSON 복원,320/390/1440px 세후 결과 화면을 검증합니다. 기존 검사에서는 현재 JSON 기대 버전만5로 올리고 과거 버전 fixture는 유지합니다.

## Milestone18과 집중 검증

사용자 요청(2026-09-26)에 따라 로컬 검증은 변경한 계산·저장·대표 UI 경로에 집중하고, 작은 변경마다 전체 회귀를 반복하지 않는다. 여러 변경을 묶은 최종 PR CI에 전체 회귀를 맡기며 main CI·Pages·공개 대표 흐름 확인은 유지한다. 금융 계산·데이터 보존의 관련 검증을 생략하거나 테스트를 약화하지 않는다. 실패/실질적 코드 변경이 없으면 통과 결과를 재사용한다.

이번 로컬 범위는 drawdown/goal-plan/withdrawal 단위 검사, drawdown 대표 흐름(기간 충당/13개월 부족/모바일/차트/백업·새로고침)과 목표 저장 보존입니다. 원가 감소·세전 환산·월별 반올림·미상 중단·안전정수·기간 상한을 검증합니다. 기존 전체 테스트는 최종 CI에서 실행합니다.

기존 FIRE 초기화·저장 시나리오는 처음부터390px에서 실행합니다. 입력 도중 화면 크기를 바꾸면 진행 중인 부드러운 스크롤과 새 레이아웃이 경쟁해 클릭이 시간 초과될 수 있습니다. 모바일 넘침·계산 무효화·초기화·새로고침 검증은 유지하고, 창 크기 변경 자체는 전용 반응형 테스트에서 확인합니다.

## Milestone19 한국어·소득

기존 UI 테스트의 한국어 접근성 이름/오류 기대를 갱신하며 단언은 유지합니다. HTML/manifest의 ko, 앱 기본 문구의 일본어 잔존 없음, 엔 표기와 한국어 모바일 레이아웃을 확인합니다. 소득 시작·0/초과 소득·미래 차입 금지·세금/원가 미상·물가·누계 overflow를 검증합니다. v6→v7 읽기 이행과 일본어 계좌명/메모 원문 보존, 소득 저장·JSON 복원·새로고침을 포함합니다. 작은 변경마다 전체 검증하지 않고 관련 검사를 묶고 최종 CI에 전체 회귀를 맡깁니다.
