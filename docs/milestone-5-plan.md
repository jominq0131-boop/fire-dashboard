# Milestone 5 월별 입력 설계안

상태: 2026-09-04 사용자 승인 후 Issue #17 / feat/monthly-records에서 로컬 구현·검증했다. 최초에는 선행 안전 보강 head `92f09af`에서 분기했으며, 이후 사용자 배포 승인으로 PR #16을 병합하고 PR #18을 main 기준으로 전환했다. 이 설계 문서의 구현 설명만으로 배포를 확정하지 않으며 실제 검증은 PR #18의 릴리스 기록을 따른다.

## 입력과 중복 정책

- 현금흐름은 월마다 하나이며 수입·소비 지출·투자 납입을 별도 저장한다. 잔액은 월과 계좌마다 하나다. 두 입력은 별도 저장 버튼으로 다루고 합계나 FIRE 지표는 이번 범위에 넣지 않는다.
- 월은 정확한 YYYY-MM, 입력 지원 범위는 1900-01~2199-12로 제한한다. 300년의 고정 범위로 시간 경과에 따라 기존 기록이 무효화되지 않는다. 월은 UTC 변환 없이 달력 키로 취급한다. 미래 월도 명시적으로 입력 가능하다.
- 금액은 0~Number.MAX_SAFE_INTEGER의 정수 엔. 빈칸은 미입력이며 0으로 변환하지 않는다. 부호·소수·지수·쉼표 표기를 거부하고 최대 16자리 숫자 문자열을 검증한 뒤 변환한다.
- 메모는 선택 사항이며 최대 1,000 UTF-16 코드 단위. ID는 최대 100, 시간은 실제 존재하는 날짜의 UTC ISO 형식 YYYY-MM-DDTHH:mm:ss.sssZ로 제한한다. createdAt은 수정 시 보존한다.
- 신규 월/계좌 조합이 이미 있으면 덮어쓰지 않고 편집을 안내한다. 수정 시 최초 읽은 레코드와 저장값을 같은 트랜잭션에서 비교하고 충돌하면 입력을 보존한다.
- 잔액은 존재하는 계좌만 참조한다. 휴지 계좌도 과거 기록 보정용 입력/수정을 허용하고 화면에 휴지 상태를 표시한다. 계좌 휴지로 잔액을 지우지 않는다. 참조 계좌 확인은 저장과 같은 트랜잭션에서 한다.

## IndexedDB v2

기존 모델의 필드와 id 기본키를 유지한다. accounts는 변경하지 않고 두 빈 저장소만 추가한다.

| 저장소                  | keyPath | 인덱스                                        |
| ----------------------- | ------- | --------------------------------------------- |
| monthlyCashFlows        | id      | month: unique                                 |
| accountBalanceSnapshots | id      | [month, accountId]: unique; month: non-unique |

v0→v2는 기존 v1 계획 다음 v2 계획을 순서대로 적용하고, v1→v2는 위 빈 저장소/인덱스 생성만 실행한다. v2 재열기는 무변경이다. 전체 계좌나 이력을 조회·복제·변환하지 않으며 시간·난수·샘플 데이터를 마이그레이션에 사용하지 않는다. 실패는 업그레이드 트랜잭션으로 롤백하고 미래 버전은 거부한다. 기존 계좌 어댑터도 동일한 DB 버전과 공통 연결 지점을 사용한다. JSON 버전과는 별개다.

## 자원 한도와 실패 처리

- 화면은 선택한 한 달만 읽는다. 현금흐름 최대 1개, 잔액 최대 100개, 계좌 최대 100개다. 기간/전체 이력 API와 차트는 이번에 추가하지 않는다.
- 현금흐름 총 3,600개, 잔액 총 360,000개가 입력 범위와 계좌 상한으로 정해지는 최대다. 생성 시 같은 readwrite 트랜잭션에서 count를 확인한다. 총량 확인은 객체 전체 읽기를 동반하지 않는다.
- 월 인덱스 count 후 제한 조회하며 초과 상태면 오류로 중단한다. 전역 count 상한도 조회 전에 확인한다. 조용한 누락이나 자동 삭제를 하지 않는다. 상한에서 정상 기존 레코드 수정은 허용한다.
- 단일 잔액 저장을 기본으로 하여 미입력 계좌를 0원으로 자동 생성하지 않는다. 성공 표시는 commit 이후에만 한다. 저장 실패·용량 부족·blocked·충돌 시 입력과 기존 기록을 유지한다.
- 저장 객체는 선언한 필드만 허용한다. 외부 코드가 넣은 거대 단일 객체의 읽기 비용 및 Chrome 전체 메모리까지 제한한다고 주장하지 않는다.

## 작은 구현 단위와 승인 후 검증

1. 월·금액·시간 검증과 월별 저장 계약: 날짜 범위 끝점, 윤년/잘못된 날짜, 5자리 연도, 소수/지수/안전 정수 경계, 빈칸과 0, 메모 길이 테스트.
2. v2 마이그레이션과 어댑터: v0/v1/v2, 계좌 필드 보존, 업그레이드 실패 롤백, 고유 인덱스, 동시 생성/수정 충돌, 없는 참조, 휴지 계좌, 상한 및 제한 조회 테스트. 총량 경계는 count 응답을 제어해 대량 시딩 없이 검증하고 실제 IndexedDB 소량 통합 테스트와 결합한다.
3. 월 선택과 별도 현금흐름/계좌 잔액 입력 UI: 재열기·새로고침 복원, 월 전환 시 미저장 입력 경고, 실패 시 입력 보존, 빈칸과 0 표시, 최대 100행을 격리 Chromium에서 검증한다.

이번 구현은 Issue #17의 짧은 브랜치에서 위 순서대로 구현·검증하고 하나의 후속 PR로 검토한다. 월별 검증과 v2 어댑터·UI를 함께 검증하는 범위이며 관련 문서를 함께 갱신한다. Vitest와 Playwright 작업자는 각각 1개다. 기존 테스트를 유지하며 새 의존성·외부 서비스·실제 사용자 데이터는 사용하지 않는다. JSON 백업, FIRE 예측, 동기화, 전체 히스토리는 후속 범위다.
