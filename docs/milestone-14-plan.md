# Milestone 14 — FIRE 계획 영속 저장과 백업

## 사용자 문제

FIRE 입력과 비교는 새로고침하면 사라져 반복 사용하기 어렵고, JSON 백업으로 다른 브라우저에 옮길 수도 없었습니다. 작은 일본어 보조 문구도 모바일에서 읽기 어려웠습니다.

## 구현 계약

- IndexedDB v4에 `firePlans(id)` 저장소를 추가합니다. 기존 레코드를 읽거나 다시 쓰지 않는 결정론적 추가 마이그레이션이며 실패 시 이전 버전 전체를 보존합니다.
- 입력 중인 문자열, 마지막으로 계산한 완전한 가정, 최대3개 비교 가정을 하나의 `primary` 계획으로 저장합니다. 빈 초기 화면은 레코드를 만들지 않습니다.
- 계산 결과 점은 저장하지 않고, 저장한 가정을 현재 계산식으로 다시 계산합니다.
- 저장은 이전에 읽은 계획과 비교해 다른 탭의 변경을 덮어쓰지 않습니다. 실패해도 현재 입력은 화면에 남깁니다.
- JSON v3은 `firePlan`을 추가합니다. v1/v2는 계획 없음으로 결정론적으로 읽고, 서로 다른 기존 계획과 가져온 계획은 전체 복원을 취소합니다.
- 일본어가 포함된 표시 텍스트는 계산된 글자 크기12px 미만이 되지 않게 합니다. 모바일 하단 탭도12px을 사용합니다.

## 한도와 검증

계획은1개, 비교는3개, 입력 문자열은16 UTF-16 단위입니다. DB v3→v4 보존, 업그레이드 롤백, 손상·초과·탭 간 충돌, JSON 구버전 정규화·왕복·원자적 충돌, 새로고침과 다른 브라우저 복원을 합성 데이터로 검증합니다. 계산식, 기록 상한, 외부 서비스와 동기화 구조는 변경하지 않습니다.
