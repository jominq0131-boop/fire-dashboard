# Milestone 17 — 취득원가와 세후 인출액

[Issue #49](https://github.com/jominq0131-boop/fire-dashboard/issues/49). 목표 도달 시 세전 매도액과 추정 세금·세후 수령액을 구분합니다.

## 계산 계약

- 현재 과세계좌 평가액과 총 취득원가는 별도 입력입니다. 원가는 미상(빈칸)을 허용하고 평가액으로 추정하지 않습니다. 손실 중인 원가는 평가액보다 클 수 있습니다. 평가액0이면 원가0/빈칸만 허용합니다.
- 시작 과세계좌가0이면 원가도0으로 계산할 수 있습니다. 기존 보유분의 원가가 미상이면 이후 매수로 미상을 해소하지 않습니다. 잔액 기록 재불러오기는 원가를 빈칸으로 초기화하여 재확인하게 합니다.
- 목표까지의 기존 월별 투영/NISA 배분은 유지합니다. 과세계좌 신규 매수액만 원가에 더하고, 수익은 원가를 늘리지 않습니다. 원가 중간 누계는 BigInt로 유지합니다.
- 연/월 세전 매도액은 기존 계산을 보존합니다. 주식 총액에 대한 과세계좌 평가액 비율로 과세 매도액을 반올림하고 나머지를 NISA 매도로 배분합니다. 현금은 제외합니다.
- 과세 이익 = 과세 매도액 × max(과세 평가액−원가,0)÷과세 평가액. 추정 세금 = 과세 이익 × 가정 세율. 세후 수령액 = 세전 매도액−세금. 각 단계는 BigInt 중간 연산 후 정수 엔 절반 올림입니다. 과세 매도0이면 이익/세금0, 원가 미상이고 과세 매도액이 있으면 이익/세금/세후는 미계산입니다. 단, 세율0이면 원가 미상이어도 세금0/세후 금액은 확정됩니다.
- 세율은0~100%, 소수3자리이며 정수 천분의1퍼센트로 변환합니다. 초기20.315%는 현재 제도를 참고한 수정 가능한 가정이며 도달 연도와 관계없이 사용합니다. 미래 법정 세율 자동 예측은 하지 않습니다.
- NISA 매도는 비과세로 계산합니다. 원가 총액과 평가액을 하나의 포트폴리오로 비례 배분한 추정이며 종목별 세무 계산, 손실 환급, 손익통산/이월공제, 수수료, 외국세는 포함하지 않습니다.
- 월액은 동일 도달시점에서 연율÷12를 적용한 독립 계산으로, 연액÷12와 반올림 차이가 있을 수 있습니다. 매월 연속 매도·도달 후 자산 유지 시뮬레이션이 아닙니다. 미도달/중단이면 도달 후 세후 금액도 표시하지 않습니다.
- 국세청 [양도소득 계산과 세율](https://www.nta.go.jp/taxes/shiraberu/taxanswer/shotoku/1463.htm), [취득비](https://www.nta.go.jp/taxes/shiraberu/taxanswer/shotoku/1464.htm), 금융청 [NISA](https://www.fsa.go.jp/policy/nisa2/know/) 확인:2026-09-26. 실제 신고액은 이 단순 모델과 다를 수 있습니다.

## 저장과 이행

DB v5의 저장소/인덱스는 유지합니다. 구13필드 목표 계획을 제한 조회한 뒤 검증하고, 메모리에서만 taxableCost 빈칸과 taxRate "20.315"를 추가합니다. 모든 기존 필드·referenceMonth·updatedAt과 원본 DB 값은 읽기/내보내기로 변경하지 않습니다. 사용자 편집의 commit에서 새15필드 계획을 저장합니다. 혼합/누락/추가 필드,16자 초과는 거부합니다. 계획1개/count 선검사/이전값 비교/직렬 저장 큐를 유지합니다. 구버전 앱은 새 필드를 손상으로 거부하므로 새 계획을 조용히 덮어쓰지 않습니다.

JSON v5는 같은 최상위6필드를 유지하며 목표 계획15필드를 요구합니다. v4는 정확히 구13필드 계획만 받아 결정론적으로 이행하고 v1~v3는 기존 경로를 유지합니다. 버전과 다른 형태는 거부합니다. 기존 세금 설정과 다른 구계획 복원도 충돌로 전체 취소하며 현재 자료를 덮어쓰지 않습니다. 빈 브라우저에는 구/신 백업 모두 복원 가능합니다.32 MiB/기존 레코드 상한은 유지합니다.
