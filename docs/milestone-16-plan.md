# Milestone 16 — 목표 도달형 입력 저장

[Issue #44](https://github.com/jominq0131-boop/fire-dashboard/issues/44). 목표형 입력을 새로고침과 JSON 복원에서도 보존합니다.

## 계약

- DB v5는 v4에 빈 goalPlans(id) 저장소만 추가합니다. 기존 기록과 firePlans는 읽거나 다시 쓰지 않습니다. 실패 시 업그레이드 전체가 롤백됩니다.
- 목표 계획은 primary 한 개, 13개 입력 문자열 각각 최대16 UTF-16 단위, referenceMonth와 updatedAt만 저장합니다. 미완성/계산 불가 입력도 보존하며 계산할 때 별도로 검증합니다.
- count 후 getAll(undefined, 1)로 읽습니다. 손상/상한 초과/다른 탭의 변경은 자동 복구나 덮어쓰기 없이 오류로 알립니다. 저장 성공은 트랜잭션 완료 뒤 표시합니다.
- 기본 화면을 여는 것만으로 계획을 만들지 않습니다. 편집 후 저장 큐에서 오래된 대기를 건너뛰고 최신 입력을 저장합니다. 저장 실패 시 입력을 유지합니다.
- referenceMonth는 최초 입력 월 또는 마지막 성공한 계산의 시작 월입니다. 단순 편집으로 과거 기준 월을 갱신하지 않습니다. 이전 월이면 잔액과 올해 NISA 매수액 확인 안내를 표시합니다. 이전 NISA 사용량을 임의로 초기화하지 않습니다.
- 계산 결과/차트 점/기록 출처 설명은 저장하지 않습니다. 복원 직후 결과는 숨기고 입력 확인 후 현재 월 기준으로 다시 계산합니다. 기존 FIRE 비교 계획은 독립적으로 유지합니다.
- JSON v4는 goalPlan 필드를 추가합니다. v1/v2는 두 계획 null, v3는 기존 firePlan 보존/goalPlan null로 결정론적으로 정규화합니다.
- 기존 32 MiB 상한, 레코드 검증과 추가 방식 복원을 유지합니다. 같은 계획은 건너뛰고 다른 목표 계획과 충돌하면 금융 기록을 포함한 전체 복원을 취소합니다. 구버전 백업을 가져와도 저장된 목표 계획은 보존합니다.
- 복원 후 저장 큐가 끝난 다음 목표 입력을 다시 읽습니다. 저장 중에는 완료 표시를 기다린 후 새로고침/백업하도록 안내합니다.

## 검증과 후속 범위

합성 데이터로 미완성 입력, 16/17자 경계, 구버전 정규화, 왕복/충돌 보존, 실제 DB 업그레이드와 실패 롤백, 탭 충돌, 손상/초과, 새로고침과 별도 브라우저 복원, 연도 경계 안내를 검증합니다. 실행 결과는 [작업 기록](work-log.md)에 기록합니다.

세후 인출, 도달 후 지속성, 자동 동기화와 외부 서비스는 후속 범위입니다. 새 의존성은 추가하지 않습니다.
